# QUANTUM UNKNOWN — QuantumCore 0.2.0

Minecraft Java Edition **1.21.1** / **NeoForge 21.1.262** / **Java 21** 向けのソースプロジェクトです。

> 注意：このZIPはソース一式です。この実行環境にはGradleがなく、外部ネットワークも利用できなかったため、ここでMODのJARをビルドしたりMinecraft上で起動テストしたりすることはできていません。ゲームでの検証済み完成品としては扱わないでください。

## 実装した中核機能

### 1. Recipe Seedとレシピ出力のランダム化

- ワールドごとにランダムなRecipe Seedを保存します。地形シードとは別です。
- `/quantum seed` でRecipe Seed、マッピング状態、ハッシュ、生成器バージョンを確認できます。
- ワールドに入った直後、最初の有効なクラフトレシピが評価される前に、管理者は `/quantum seed set <seed>` で指定できます。
- 同じMOD構成・同じ生成器バージョン・同じRecipe Seedなら同じマッピングが生成されます。
- 最初の対象はバニラの道具・防具レシピです。同じ素材ティア内で出力を入れ替えます。たとえば木の道具のレシピ群は木の道具同士、鉄の道具は鉄の道具同士で対応が変わります。
- すべてのレシピを無差別に混ぜる方式ではありません。作業台、棒、かまど、エンダーアイなどの進行必須レシピは固定し、MOD独自のレシピはランダム化対象外です。

### 2. 未観測オブジェクトの見た目を統一

- 未観測の通常ブロックは、共通の灰色の立方体モデルとして表示されます。
- 未観測アイテムのインベントリ表示・ドロップ表示も、共通モデルで隠します。
- 未観測アイテムのツールチップは「未知の物体」と表示します。
- ブロックの当たり判定や本来の内部IDは変えません。見た目だけを差し替えるため、ゲームの内部処理が壊れにくい設計です。
- 階段・フェンスなど複雑な形状も、未観測中は立方体に見えます。

### 3. 観測と情報開示

- ブロックを採掘すると、そのブロックと対応するブロックアイテムを観測済みにします。
- アイテムの取得、クラフト、消費アイテムの使用でも観測状態が更新されます。
- クラフト時には作業台の配置と実際の出力を研究ノートに保存します。
- 発見情報はワールド保存データに記録され、マルチプレイでは全員に同期されます。
- `/quantum notebook` で発見済みの配置と出力を確認できます。

### 4. JEI・バニラレシピブックの制限

- バニラの作業台・かまど・燻製器・溶鉱炉・石切台・鍛冶台などのJEIレシピカテゴリを隠します。
- 未観測アイテムはJEIのアイテム一覧から除外し、観測したアイテムを再表示します。
- 未観測アイテムのNBT/コンポーネント違いの表示候補も保存して、観測時に可能な範囲で戻します。
- バニラのレシピブックを開く操作も無効化します。
- JEIは任意依存です。JEIなしでも観測・クラフト側の仕組みは動く設計ですが、JEI以外のEMI/REIにはまだ連携していません。

### 5. 進行可能性の安全検証

- レシピIDの集合が一致すること、出力アイテムの頻度が保たれること、出力が元と同じ道具/防具ティアに留まることを検証します。
- 棒、作業台、かまど、エンダーアイ、各ティアのツルハシなど、バニラの進行に必要な出力が存在するか確認します。
- 検証に失敗した場合はランダムマッピングを採用せず、バニラ出力へフォールバックします。
- この方式により、このMODのランダム化が必須レシピを他アイテムに置き換える問題を避けます。ただし、未知のサードパーティMODや任意のデータパック、特殊なワールド条件まで数学的にクリア保証するものではありません。

## ゲーム内コマンド

- `/quantum status` — 進行段階、観測数、Recipe Seed、検証状態を表示
- `/quantum seed` — Recipe Seed、マッピングハッシュ、生成器バージョンを表示
- `/quantum seed set <seed>` — 管理者用。最初のマッピング生成前にシードを指定
- `/quantum notebook` — 発見済みのクラフト配置と実際の出力を表示

**同じレシピ構成を再現する手順：** 1つ目のワールドで `/quantum seed` を実行し、Recipe Seedを控えます。別ワールドを作成したら、最初の有効なクラフトレシピを作る前に `/quantum seed set 控えたシード` を実行してください。シード再現には、MOD構成と生成器バージョンも揃える必要があります。

## ビルド（Windows PowerShell）

JDK 21とインターネット接続が必要です。プロジェクトフォルダで実行してください。

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build.ps1
```

`build.ps1` はシステムにGradleがあればそれを使い、なければGradle 8.14.3を `.tools` にダウンロードして `clean test build` を実行します。成功すると `build\libs\` にJARが作られます。Minecraft 1.21.1 + NeoForgeのクライアントに入れて動作を確認してください。マルチプレイではサーバーと接続クライアントの両方にMODを入れてください。

## 現時点の制限

- 未観測表示の対象は通常のベイク済みモデルです。水・溶岩などの液体描画、ブロックエンティティ、独自の特殊レンダラーなどから視覚的なヒントが漏れる場合があります。
- レシピ出力のランダム化対象は、バニラの道具・防具の一部です。特殊レシピ、醸造、鍛冶、金床、機械レシピ、MOD独自レシピはまだ書き換えません。
- JEIの連携、Mixinのターゲット、モデルのベイク処理は、実際のMinecraft 1.21.1環境でビルド・起動テストが必要です。
